# Star 文档入口

本目录保存当前开发所需的架构、设计理由、实现状态和讨论方案。新工作从仓库内文档接续，旧 OpenSpec 目录已移除，历史资料保留在 Git 中。

## 阅读路径

开始开发时先读 [项目上下文](../CONTEXT.md) 和 [架构约束](architecture.md)，然后根据任务选择下面的分支；无需通读全部历史。

| 本轮要做什么 | 应读取的内容 |
| --- | --- |
| 安装、运行脚本或启动控制台 | [README](../README.md) |
| 确认开发规则、测试和提交方式 | [AGENTS](../AGENTS.md) |
| 判断能力属于哪一层、怎样接平台 | [架构约束](architecture.md)、[ADR 0002](adr/0002-ports-and-adapters.md) |
| 调整创作方式或用户流程 | [项目上下文](../CONTEXT.md)、[ADR 0001](adr/0001-agent-authored-tasks.md) |
| 新建具体任务、选择数据根或调整资源隔离 | [README](../README.md)、[ADR 0006](adr/0006-local-task-workspaces.md)；任务上下文读取所选外部工作区 |
| 修改结果、停止、验证或任务完成语义 | [ADR 0003](adr/0003-results-and-verification.md)、[当前状态](current-state.md) |
| 增加控制台或诊断能力 | [ADR 0004](adr/0004-small-console.md) |
| 设计循环恢复、重试或子任务组合 | [当前状态](current-state.md)、[恢复机制讨论稿](design/local-recovery.md) |
| 选择下一项产品工作 | [重启计划](restart-plan.md) |
| 了解旧需求为何曾这样实现 | 按 [历史查询方法](adr/0005-repository-documentation.md#历史查询) 读取旧提交中的资料，再与现有代码核对 |

## 各类文档的职责

| 内容 | 维护位置 | 更新时机 |
| --- | --- | --- |
| 产品方向、作者与领域语言 | `CONTEXT.md` | 用户目标、协作方式或概念含义改变 |
| 稳定职责、依赖方向和接口边界 | `docs/architecture.md` | 模块职责或跨层接口改变 |
| 重要选择的背景、代价与重审条件 | `docs/adr/` | 实际作出或替换跨模块设计决策 |
| 目前支持什么、已知缺口与验证证据 | `docs/current-state.md` | 实现和验证状态发生变化 |
| 尚待选择的方案 | `docs/design/` | 设计讨论推进；定案后链接对应 ADR |
| 近期阶段与验收建议 | `docs/restart-plan.md` | 工作优先级调整 |
| 命令和使用方法 | `README.md` | 用户可见入口或用法变化 |

本目录只维护框架资料。具体任务的脚本、模板、玩法说明、运行记录和证据保存在外部任务工作区，主仓文档只解释通用接口与隔离约定。

## 状态与冲突处理

- 当前用户指令优先。文档记录已确认的选择，不能替代用户对新范围的决定。
- 已采纳的 ADR 解释选择，架构文档规定稳定边界；讨论稿和路线建议不自动成为约束。
- 当前行为用代码、公开接口测试和必要的真实验证核对。实现偏离已采纳设计时，明确记录实现欠账；不要把缺陷改写成架构原则。
- 发现文档与实现冲突，先判断是文档过时、实现缺陷还是本轮要改变的决策，再同步对应的一处来源。
- OpenSpec 的旧规格、任务勾选和示例只提供历史线索。已删除能力以当前实现和 ADR 为准。

## 维护方式

同一规则保留一个主要维护位置，其他文档用链接引用。小修复更新相关现状或用法即可；只有影响职责、契约或长期维护成本的选择才需要 ADR。

设计定案时，在 ADR 中记录状态和取舍，并在原讨论稿标明去向。已解决的缺口从当前状态中移除或简述解决证据，避免留下过时的待办。ADR 被替代时保留原记录并链接替代项。

文档改动完成后检查相对链接、代码入口、状态标记和术语一致性，再运行 `git diff --check`。文档整理无需新增测试或重复运行完整测试；代码行为变化按 [AGENTS](../AGENTS.md) 的验证要求执行。
