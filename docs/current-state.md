# Star 当前实现快照

快照日期为 2026-11-14。本文供接手项目、讨论下一步或修改相关行为时快速定位。
它描述当前代码与已获得的证据；架构约束见 [architecture.md](architecture.md)，运行方法见 [README](../README.md)。
实现变化后更新对应条目；缺口解决后删除旧问题，保留必要的验证证据。

## 使用方向与作者方式

- 用户已明确：由用户描述任务和结果要求，Agent 负责观察目标画面、补齐流程、生成并维护任务。
- 当前使用目标是完成一款游戏的实际日常任务；具体业务任务、素材与进度由外部本地工作区维护。
- 函数任务使用 Python 文件中的 `TASK` 字面量与同步 `run(ctx)`，全部活动任务和通用示例使用这一格式。任务由 Agent 编写维护。
- 用户选择 macOS 原生优先。SwiftUI/AppKit 壳组合素材准备与任务运行，Python 后台通过本地管道提供独立用例，旧网页入口和 HTTP UI 已移除；边界见 [ADR 0008](adr/0008-native-macos-desktop.md)。
- 准备用例提供选窗、冻结截图、点击取点和框选保存模板，不依赖任务执行；服务边界见 [ADR 0007](adr/0007-preparation-and-execution.md)。
- 创建、编辑、保存任务仍通过文件完成；原生壳可显式重新加载任务，也可在空闲时通过关闭旧后台切换工作区。没有完整编辑器或自动热加载。
- 本机原生应用已完成 SDK 构建与基础窗口、权限和截图验证。实时识别的最新自动化与原生验证分别记录在本文末尾。
- 方向与阶段讨论见 [重启计划](restart-plan.md)。函数任务支持局部异常恢复，恢复讨论的历史背景见 [设计草案](design/local-recovery.md)。
- 本文记录的实现限制和债务不构成未来架构要求；已决定事项另见 [ADR 索引](adr/README.md)。

## 从任务描述到执行

以下是 Agent 接到任务后需要完成的工作；用户提供目标和必要业务选择，Agent 负责可以自行观察、采集与验证的部分。

1. 明确起始画面、前置条件、动作、可观察的完成标志和停止条件。
2. 选定仓库外的任务工作区，准备其中的 `assets/` 模板图片；固定点位在素材准备页采集窗口相对坐标。
3. Agent 在该根创建 `scripts/*.py`，声明 `TASK` 并实现 `run(ctx)`；状态、共享搜索和窗口尺寸使用同根 `assets/window-states.json`。真实运行的 `target.backend` 只能是 `macos-window` 或 `macos-window-background`。
4. 通过全局 `--workspace PATH` 使用 `list` 列出任务、报告坏文件，使用 `details` 展示入口与声明依赖。
5. 模拟运行检查一组固定假条件下的执行路径；随后在真实目标中核对操作和任务结果。
6. 根据真实失败点修改任务或资源，再分别报告自动化验证与真实任务验证。

[项目任务装配](../src/game_automation/portable/application/project_tasks.py) 读取所选根 `scripts/` 顶层的 Python 任务文件，无参数时使用仓库根的通用示例。
工作区按文件名排序加载任务。名称来自 `TASK.name`，与文件名可以不同。非 Python 文件被忽略。Python 辅助文件可使用以下划线开头的名称，任务通过相对导入复用。
单个文件格式错误或名称重复会被隔离，其他有效任务继续可用。
`star --workspace PATH list/details/run/run-plan/ui` 选择已存在的目录，参数放在子命令之前。路径解析与入口传递见 [CLI](../src/game_automation/platform/local_desktop/entrypoints/cli.py)，同根资源约定见 [project_assets.py](../src/game_automation/portable/application/project_assets.py) 和 [ADR 0006](adr/0006-local-task-workspaces.md)。

| 入口 | 可用控制 | 生命周期与边界 |
| --- | --- | --- |
| CLI `list/details/run` | 查列表、查依赖、单任务运行；CLI 默认真实运行，需显式选择模拟 | 每次调用重新发现 Python 元信息 |
| CLI `run-plan` | 按顺序运行多个已有任务，选择停止或继续策略 | 每项使用自己的原生窗口目标；dry-run 不打开窗口 |
| CLI `recorder` | 打印鼠标屏幕坐标和颜色；终端保持焦点，按 `1` 记录、`Q` 结束 | 不创建任务或模板；屏幕坐标不能直接用于任务 |
| 原生壳 `ui` / `star-desktop` | 工作区选择、素材准备、任务详情、模拟/真实运行、停止和诊断 | macOS 13+；后台单实例，工作区切换先回收旧进程；本机原生基础验证已完成，新增能力以验证记录为准 |
| `prepare` | 打开同一原生壳的素材准备入口 | 要求显式工作区；不启动 HTTP；仅进入执行功能时加载 catalog |

原生协议只允许一个后台任务会话；运行中拒绝新的素材操作、工作区切换和重复启动。
平台初始化或执行抛出普通异常时，用例返回失败原因；后台会话还有独立兜底，记录结束状态。普通执行失败完成资源回收后可重新运行；原生停流失败则保留进程级故障租约，后台重启前不能建立新的原生会话。
原生会话通过标准管道请求与后台通信。超时或异常退出显示诊断并回收进程，不自动重放动作。关闭窗口、Command+Q 与信号退出共用关闭路径；后台收到 shutdown、EOF 或 SIGTERM 时取消并等待线程，释放临时帧和工作区锁。
原生运行页按任务 `target` 打开原生窗口会话；没有暂停、单步执行或从中断点恢复。未声明原生后端的真实运行直接失败。
入口代码见 [CLI](../src/game_automation/platform/local_desktop/entrypoints/cli.py)、[后台协议](../src/game_automation/platform/local_desktop/entrypoints/desktop_backend.py) 和 [原生会话](../native/StarDesktop/Sources/StarDesktop/Session.swift)。

## 素材准备与执行隔离

[PreparationService](../src/game_automation/portable/preparation/service.py) 只消费窗口、截图、图像编辑和模板存储端口，不引用 runner、任务目录或运行控制会话。原生后台按请求映射到准备或运行用例，执行服务延迟创建。准备逻辑可通过 fake 窗口和内存画面测试。

- 冻结帧绑定 ID、时间、窗口范围和 PNG 尺寸；取点返回窗口相对点及截图时的屏幕点，任务只使用窗口相对点，裁图使用同一帧像素。
- 当前服务只保留一帧，新捕获会使旧帧失效；旧 ID 返回冲突，捕获失败也不能继续操作旧帧。
- 名称只作为 assets 下的 PNG 文件名；拒绝越界裁图、路径名称及已有文件覆盖。点位和资源片段由原生界面展示；普通模板保存不写任务，专用“保存状态素材”入口登记下述窗口观察规则。
- 准备和模板匹配复用 `screen_capture.py` 的像素比例转换；真实运行的图像来自独立窗口流。真实准备截图限主屏幕内的 macOS 窗口，超出范围报错；窗口必须保持可见且无遮挡，同进程重复标题需先消除歧义。
- 准备选窗不会改变任务运行目标。任务通过 `target` 声明原生窗口；真实运行不接受命令行覆盖，也不再提供屏幕绝对坐标路径。实时识别使用当前所选窗口启动独立只读观察会话，不复用准备帧；观察 UI 缓存不驱动动作。任务通过独立运行会话复用窗口规则；截图回放尚未接入。

## 实时窗口状态识别

- 窗口规则支持 `method: "points"` 固定多点颜色特征，按截图原始像素取色并允许有界整组平移，全部点通过才命中。纯多点不加载CV或整图数组；UI显示通过点数。格式、排序及参考PNG兼容边界见 [ADR 0011 多点补充](adr/0011-priority-window-observation.md#2026-11-07-多点匹配补充)。配置由Agent维护，准备UI仍登记模板。

- 素材准备页支持填写状态名、阈值与搜索范围，保存模板并登记窗口规则。搜索范围由截图像素换算为窗口内逻辑坐标，模板保留原像素。
- 规则保存在所选工作区的 `assets/window-states.json`，包含逻辑窗口尺寸及完整截图像素尺寸。这是唯一的状态与共享搜索文件。
- 实时识别页支持每秒 1、2 或 5 次检测，默认每秒 2 次及连续两帧确认。展示当前状态、本帧候选、每项匹配分数与位置、耗时、时效及有界状态历史。
- macOS14+实时观察使用低频ScreenCaptureKit单窗流，采集频率跟随所选1/2/5Hz，默认2Hz。工作线程启动，独立串行队列只复制最新像素；每轮素材共用同一张窗口画面，不激活应用或发送输入。窗口编号、逻辑尺寸和像素尺寸变化后，不静默接管或缩放模板。
- 源时间及独立事件序号参与新鲜度和连续确认；重复缓存不续期也不增加确认。有效idle仅证明系统确认画面未变化。停止等待系统与回调屏障，回收失败保留停止中并由宿主监督；见[ADR 0010](adr/0010-window-stream-observation.md)。
- 观察会话使用明确阶段及不可变快照。停止先撤销有效状态，迟到帧不能重新发布。首帧超时、慢帧、窗口不可用和截图失败均不沿用旧状态。
- 观察停止不阻塞协议线程。原生壳有独立停止期限，必要时沿既有后台回收路径结束采样，实际退出前不释放运行槽。启动和状态回调使用阶段及代次约束。
- 观察期间禁止采集、登记或执行任务。观察 UI 的当前状态只用于展示；任务在观察停止后，用独立会话的新画面复用同一份多点/优先级规则，为执行核心提供状态输入。两类会话不共享缓存或连续确认历史。多素材组合条件与同时存在的主状态、覆盖层仍未实现。
- 默认打开约520×820点的右侧窄版观察窗，可置顶；展开准备恢复宽版，游戏尺寸与位置不被修改。
- 性能面板按已完成采样统计素材数、截图/识别/整轮成本、失败及超预算轮次；分位数保留最近最多120轮。停止保留统计、新观察清空。离线冻结帧工具对比重复请求规模及ROI，不将其当作不同素材或实机全流程成本。
- 设计边界见 [ADR 0009](adr/0009-live-window-observation.md)，用户操作见 [原生应用说明](../native/StarDesktop/README.md#登记素材并开始实时识别)。

## 桌面权限引导

- 原生壳顶部展示实际 Python 后台的窗口控制和屏幕截图权限，不因打开应用自动申请权限。
- 对应按钮发起单项系统申请；拒绝或尚未批准时不宣称成功。回到应用可自动查询，也可手动检测或重启后台。
- 读取窗口与准备截图缺少权限时显示中文引导，运行中的权限申请被后台拒绝；模拟运行仍可使用。
- 开发构建支持 `--install` 安装到固定的 `~/Applications/Star.app`，支持固定本机证书签名及跨内容身份校验，未配置时警告并使用临时签名，签名失败不降级。首次迁移到固定证书仍需重新登记一次；实机重建后的权限连续性见验证记录。授权最终由用户在系统界面确认；不同启动链路的归属以实际系统提示为准。

## 桌面生命周期和性能边界

- macOS 后台在每次管道请求到达后推进主运行循环，处理应用启动与退出事件，再执行用例。`NSWorkspace.runningApplications` 的快照依赖运行循环更新；只反复读取属性会漏掉后台启动后新开的应用。该处理属于平台后台，不进入素材准备用例或 runner。

- Python 后台通过文件锁保证每个工作区只有一个所有者；正常关闭、管道 EOF 和 SIGTERM 均走同一回收路径。
- 截图通过后台独占的临时 PNG 路径交付，不经 JSON Base64 传输，只缓存一帧。原生图片读取在后台任务中执行，过期结果不重新挂回已关闭或已切换的会话。
- 每个运行输出流最多保留 262144 字符和最近 2048 个事件，原生协议每次最多交付 65536 字符 stdout 和 8192 字符 stderr。诊断面板及文件也有上限。
- 原生壳先等待后台有序退出，超过 7 秒发送 SIGTERM，再等 2 秒才强制回收已确认的后台进程组。强制回收需核对最后一次操作，不能当作业务成功。
- 当前 `.app` 开发构建绑定 checkout 和 Python 环境，进行本地临时签名，尚未打包 Python、使用发布签名或公证。Swift 语法检查不代替 SDK 类型检查，真实 Mac 验收仍待执行。

## Python 函数任务

同步 `run(ctx)` 直接使用 Python 函数、分支、循环、返回值和局部异常处理。`TaskContext` 直接拥有输入、定位、轮询、期限和事件。一次任务复用同一原生窗口会话。旧格式解析、控制节点、条件对象和解释器已经移除，迁移决策见 [ADR 0015](adr/0015-python-only-tasks.md)。作者接口见 [函数任务说明](task-functions.md)，整体接入顺序见 [核心优先设计](design/core-first-execution.md)。

等待超时可局部捕获 `TaskTimeout`，直接图片点击缺图可捕获 `TargetNotFound`。用户停止通过独立信号穿过普通异常恢复，任务目录内的 Python 循环和模块顶层均检查取消。第三方阻塞调用仍需等待返回。显式期限在上下文调用及等待轮询中检查，平台暂停使用已有任务时钟扣除暂停区间。

函数任务的目标和资源来自字面量，本地命名资源自动进入依赖检查，共享搜索和状态通过 `requires` 声明。详情展示入口与声明依赖，实际动态路径来自动作事件。主仓提供 `function-task-demo`，具体业务任务继续保存在外部工作区。

任务目录统一隔离读取、编码和语法错误，包含失效文件链接。静态任务分析统一产出引用与能力事实，详情和端口装配消费同一声明。期限事件属于各自作用域，空作用域和已成功动作后的到期具有独立记录。

原生客户端以 `RunPhase` 区分运行和停止中，后续运行回复保留停止意图。停止请求幂等，停止中允许显式重启。重启复用现有后台关闭监督，确认旧进程实际退出和待处理请求清理后启动新代次。

## 资源、状态与坐标

| 概念 | 当前表达 | 生命周期或限制 |
| --- | --- | --- |
| 点位 | `resources.points` 的命名 `{x,y}` | 任务发现时保存；运行前校验声明，点击时解析坐标 |
| 图片 | `resources.images` 的名称到文件路径 | 路径相对所选根的 `assets/`，允许子目录；loader 本身不检查文件存在 |
| 区域 | `resources.regions` 的命名矩形 | 必须有正宽高；用于搜索范围 |
| 搜索 | `resources.searches` 组合图片、区域、置信度 | 通过上下文查询和点击时引用名称 |
| 任务状态 | `assets/window-states.json` 的窗口模板/多点规则 | 每轮运行加载规则并绑定尺寸；同一运行源按规则优先级截断，输入后必须获取新系统画面 |
| 共享资源 | 同一份窗口规则中的 regions/searches | 仅当被引用的搜索或区域不能由局部资源解析时加载；局部同名资源覆盖共享资源 |

共享资源装配见 [task_resources.py](../src/game_automation/portable/application/task_resources.py)，状态读取复用 [window_state_probe.py](../src/game_automation/platform/macos/adapters/window_state_probe.py)。
原生会话需要窗口规则的逻辑/像素尺寸，即使本轮不读取状态也会先校验这份配置。需要共享搜索时解析同一份配置并报告错误。dry-run 的状态是调用方给出的固定名称，不读取该文件。

`details` 的 readiness 覆盖点位、图片和状态；发现 `missing` 时返回退出码 2，CLI/UI 仍展示入口和依赖检查，`unknown` 不作为已确认缺失。
单任务运行在打开原生窗口会话前校验声明的点位、图片、搜索和区域别名，未知引用返回 `2/configuration_failed`，不会先执行前序动作。该校验不要求模拟模板文件存在，也不代替真实识图或业务验收。
任务局部图片路径相对所选工作区的 `assets/`，通用示例也遵循这一规则。
状态与共享搜索只读取所选工作区的 `assets/window-states.json`，不回退到主仓，也不按图片文件名推断状态。
候选配置自己的阈值优先于状态读取参数；状态读取默认阈值为 0.8。

- 点位和搜索区域相对任务声明的原生窗口。dry-run 没有活动窗口时按作者写下的坐标原样传递，不映射到屏幕。
- 真实运行在会话开始时绑定唯一可见窗口；运行中窗口移动或尺寸变化会失败，不在中途改绑。
- 未声明 `macos-window` 或 `macos-window-background` 的真实运行在打开设备前失败。没有命令行目标覆盖。
- adapter 处理截图像素与鼠标坐标的比例换算；模板没有自动缩放匹配，界面缩放/主题变化仍可能影响识别。

坐标规则见 [windows.py](../src/game_automation/portable/domain/windows.py)，运行装配见 [task_run.py](../src/game_automation/portable/application/task_run.py)，窗口内匹配实现见 [image_matching.py](../src/game_automation/platform/desktop/adapters/image_matching.py)。

## 模拟运行能证明什么

模拟设备只打印点击、组合键、拖拽和等待；不会读取真实桌面，也不会按等待秒数实际休眠。
模拟颜色和状态分别是固定值；模拟图片集合里的模板始终返回固定假匹配，其余模板始终不命中。
UI 自动把所选任务解析出的图片依赖全部视为找到；CLI 通过显式图片或 `--dry-run-script-images` 选择。

因此模拟运行只执行“固定假画面下的一条路径”，不能演练状态迁移：

- 任务依次要求“状态 A → 状态 B”时，任一固定模拟状态都无法走完整条成功路径。
- 图片全部模拟命中时，循环退出检查可能立即命中；这不代表真实流程分支正确。
- 无限循环配合模拟等待仍会持续快速运行和产生日志，模拟不保证自动结束。
- 模拟匹配位置来自假矩形，不能验证真实点击点、模板质量、目标应用响应或业务完成。

实现见 [dry_run.py](../src/game_automation/portable/adapters/dry_run.py) 与 `task_run.py` 的 dry-run 端口装配。
这组限制是当前替身的能力边界，未来可调整；流程预览和可迁移的模拟场景尚未实现。

## 停止与完成语义

| 情况 | 当前结果 | 后续行为 |
| --- | --- | --- |
| 按所选分支与循环规则正常结束 | `exit_code=0, completed` | 分支或循环中断可跳过静态步骤，业务结果需独立证据 |
| 点击图片未找到 | `exit_code=0, stopped_unmet_condition` | 整个任务停止，跳过后续步骤 |
| 未捕获 `TaskTimeout` | `exit_code=1, timed_out` | 任务停止，局部恢复可在函数中显式捕获 |
| Python 循环退出或局部期限被本层处理 | 由任务函数继续执行 | 检查点可在等待中退出所属流程，外层期限按身份传播 |
| UI 用户停止被执行器观察到 | `exit_code=130, cancelled` | 当前任务取消；已发生的输入不会回滚 |
| 运行配置/初始化/动作失败 | 分别为 `configuration_failed/setup_failed/failed` | 返回错误原因，后台会话结束并可再次运行 |
| Run Plan 默认遇到未完整执行项 | 普通失败保留首个未完成原因和首个非零退出码 | 停止后续任务，即使该项退出码为 0 |
| Run Plan 开启 `continue_on_error` | 普通失败或条件未满足后继续 | 用户取消始终停止后续任务 |
| Run Plan 任一项返回 `cleanup_failed` | 资源没有完成停止，整轮立即停止 | 即使开启 `continue_on_error` 也不继续建立新运行环境 |
| Run Plan 任一项返回 `cancelled` | 整轮为 `exit_code=130, cancelled` | 取消优先于此前普通失败；各项原始结果保留 |

取消是协作式检查：步骤边界、真正点击前、图片等待轮询、每组连续按键前会检查。
后台真实等待通过可取消设备包装每最多 50ms 检查取消；正在进行的平台原子调用仍可能延迟停止，原生宿主提供有界的进程回收。
`ctx.click(..., then_hotkeys=...)` 的连续组合键之间检查用户取消和期限。
实现见 [task_context.py](../src/game_automation/portable/engine/task_context.py) 与 [run_plan.py](../src/game_automation/portable/application/run_plan.py)。
相关行为测试见 [test_execution_core.py](../tests/test_execution_core.py)、[test_task_context.py](../tests/test_task_context.py)、[test_run_plan.py](../tests/test_run_plan.py) 和 [test_local_control.py](../tests/test_local_control.py)。

## 任务绑定目标窗口

顶层 `target` 需要 `application`、`window_title`、`width`、`height` 和 `backend`。前两项是非空文本，尺寸是正整数逻辑尺寸；未知字段和 backend 拼写错误会拒绝。允许的 backend 只有 `macos-window` 和显式试验 `macos-window-background`。真实运行缺少该声明时失败。模拟运行不调用真实选窗。单一路径见 [ADR 0016](adr/0016-native-window-only-runtime.md)。

显式 `backend: "macos-window"` 为一次运行打开独立 `RuntimePorts` 会话：固定唯一窗口的 PID、CG ID、标题和矩形，截图、取色、模板、多点状态与原生前台输入共用该窗口。状态读取复用 `assets/window-states.json` 的优先级/多点；不用观察 UI 的缓存。输入后必须等新的源序号和更晚的系统时间；旧帧、窗口移动/变形/替换会失败，窗口移动或尺寸变化错误显示原窗口和当前窗口的完整逻辑矩形，不在运行时更换截图源或输入 transport。输入固定采用 `foreground-session` 原生会话投递；实际发送前确认绑定进程是前台，按下前确认点位最上层可见窗口仍为绑定 CG ID，仅精确排除公开系统光标层，其他可见浮层遮挡明确失败。运行结束关闭唯一窗口流；停流失败显示 `cleanup_failed` 并阻断新的原生会话，需重启后台；Run Plan 即使设置继续普通错误，也在清理失败后强制停止。取消优先且保留清理错误。该路径要求已有窗口尺寸/像素配置，不支持后台交互，不承诺跨 Space 或锁屏。PID 投递五轮短探针未完成活动页切换，当前前台 transport 的真实验收另行记录。完整边界见 [ADR 0012](adr/0012-native-script-runtime.md)。


显式 `backend: "macos-window-background"` 是隔离的后台点击试验，复用同一窗口会话/SCK/视觉/进程租约，状态配置仍为 `window-states.json`，不使用屏幕绝对坐标。只支持 click/wait，不请求前台、不全局投递、不移动真实指针。游戏进入前台后仍使用原 PID 点击方式。同一窗口短暂不可见、矩形或采集展示变化时暂停输入，等待原始矩形与新源画面恢复后继续。恢复前重新准备尚未发送的点击，已尝试按下的点击只完成释放。暂停时间从普通等待与循环时间预算扣除，恢复等待期间可停止。固定身份丢失和系统停流等终止故障继续报错。使用完整 PID recipe 及私有 `CGEventSetWindowLocation`，符号缺失即失败；已验证私有符号可绑定及 fake 边界；Star 自有 port 的本机同桌面游戏单次“主页→活动”探针通过，新源画面确认活动页，独立30秒采样的前台进程和真实指针未变。此证据不代表其他应用或长期后台流程已验收。前台输入实现保留。依赖与边界见 [ADR 0012](adr/0012-native-script-runtime.md#显式后台点击试验)。

## 局部任务时间上限

任务通过 `ctx.deadline(seconds)` 给一段代码设置有效任务时间预算。期限包含识图和输入耗时，平台暂停期间扣除暂停时间。等待裁短到最早期限，输入前再次检查。到期抛出带作用域身份的 `TaskTimeout`，任务可捕获自己拥有的期限并继续。已开始的平台调用和必要释放可能晚于期限返回。模拟等待推进虚拟时钟，仍只验证固定假画面下的路径。
