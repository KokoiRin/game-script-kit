## 下一优先级 补足实际任务的场景回归

目标是提高修改游戏流程后的离线验证能力。

当前 dry-run 提供固定状态和固定图片命中。执行核心测试已经支持可控时钟、状态序列和匹配序列，可先复用这些能力验证具体流程。

1. 从常用任务中选一条有明确完成条件、包含多次状态变化的流程。
2. 在外部工作区保存正常完成、等待超时、目标消失和用户停止等场景的预期。
3. 通过已有 `run(ctx)` 和替身端口验证动作顺序、停止原因、超时后的局部处理与取消传播。
4. 按重复使用情况提炼所需的最小测试辅助能力，通用部分归主仓，业务场景和素材留在工作区。

完成标准为任务修改后能够离线核对主要成功和失败路径，并明确每个场景的模拟条件。真实游戏完成情况继续由用户测试和工作区证据记录。

## 随后 按重复流程提炼工作区辅助函数

在前一阶段的场景保护下，对照现有游戏任务，寻找动作、资源和失败处理都相同的片段。

- 多个任务确实共用的流程，放入工作区 `scripts/_helpers.py` 或按用途命名的辅助模块，通过相对导入调用。
- 每个辅助函数说明进入条件、结束画面和失败传播方式。
- 对照抽取前后的动作、等待与异常结果，保证调用方依赖的行为一致。
- 只有通用执行能力出现实际缺口时，再调整框架接口。

完成标准为一次共享流程修改能够覆盖其实际调用方，任务主体仍能直接读出业务顺序。
