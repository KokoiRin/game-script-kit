# Star 重启计划

更新日期：2026-10-19。以下是近期推进建议，阶段顺序可按真实使用调整；具体恢复语法和任务组合尚待设计。已确认的目标与创作方式见 [项目上下文](../CONTEXT.md)，当前能力与缺口见 [当前状态](current-state.md)，长期取舍见 [ADR 索引](adr/README.md)。

## 本轮已完成的收敛

控制台已回到脚本选择、详情、运行、停止和结果查看。截图诊断、框选、裁剪、独立图片点击、连续探测和网页运行测试已从工作区实现移除；脚本按需使用的状态读取、运行事件和开发靶场保留。理由见 [ADR 0004](adr/0004-small-console.md)，验证快照见当前状态文档。

框架主仓与本地任务数据已分离：`star --workspace PATH ...` 使用外部任务工作区；显式根不混入内置示例，一个 UI 服务绑定一个根。业务脚本、素材与玩法记录留在本地工作区。分支按通用能力短期维护，任务不再占用游戏专用分支，理由见 [ADR 0006](adr/0006-local-task-workspaces.md)。

## 第一阶段 收口已有的失败与创建链路

先让已有行为可解释、可验证，再选择新增控制语义：

2026-10-19 已补齐未知点位运行前校验、后台异常收尾和 Run Plan 取消优先级；行为与验证范围见 [当前状态](current-state.md#停止与完成语义)。本阶段其余建议仍为：

1. 明确新建、校验、重新加载和运行脚本的路径，减少 Agent 修改文件后的手工重启与重复准备。
2. 为一个具体任务列出正常、等待超时和画面意外变化的场景，核对当前模拟方式无法覆盖的部分。

验收建议：配置错误、等待未满足、设备失败、用户取消均能结束并解释；脚本修改后能确认执行的是哪份内容；自动化验证和真实桌面验证分别记录。

## 第二阶段 完成一项真实日常任务

在所选外部工作区，从现有素材中选择一项当前常用且流程稳定的日常。具体任务选择、游戏流程、素材和实测进度保存在该工作区，主仓只接收已证明需要的通用能力改动。

先明确任务起始画面、前置条件、完成标志和失败时的业务选择，再补齐实际流程。用户描述目标，Agent 观察与生成脚本，遇到会改变业务结果的选择再与用户讨论。

涉及局部恢复时，按 [讨论稿](design/local-recovery.md) 比较候选，定案后记录 ADR 并实现；当前无限循环不是自动重试，无法确认画面时不能靠重复点击推进。目标窗口和状态坐标的现有限制需在这条真实任务路径中处理或明确运行前提。

验收建议：

- 从约定起点执行到明确的任务完成标志，独立核对游戏内结果。
- 多次运行逐次记录结果，未完成的运行不能记为成功。
- 已知意外场景按约定恢复或停止；用户取消始终结束执行。
- 游戏内完成证据与步骤执行结果分别保留。

交付是在外部工作区内的一条可重复使用的任务脚本、必要资源和简短准备说明；业务资料不并入框架主仓。

## 第三阶段 降低准备成本并检验复用

根据第一条任务的真实失败记录，补齐目标窗口接入、坐标一致性或有限恢复等确有需要的能力。控制台复用应用用例和既有校验，不重新解释脚本语义。

任务稳定后，再增加同一游戏的第二项日常。比较实际重复的流程与资源，只有出现真实共享需求时才抽取公共片段或引入子任务组合。

验收建议：窗口移动、目标缺失或歧义都有明确结果；两条任务各有独立完成证据；修改共享能力后，两条任务都能回归。优先使用现有 Run Plan 串联已验证任务，其策略变化应补相应测试。

## 后续方向的进入条件

流程编辑器、OCR、Windows、多窗口、定时运行和插件体系均需有具体任务证明投入价值。辅助选点或裁图可作为创建某个步骤的一部分，避免重新长成独立调试工作台。

下一轮评审看三个实际结果：任务完成情况、失败与取消是否准确、重复使用需要多少手工准备。新增能力服务这些结果，重要取舍按仓库文档规则记录。
