# 0007：素材准备壳与脚本执行分离

- 状态：accepted
- 日期：2026-11-05（用户明确要求先分离底层能力和上层 UI）
- 性质：准备用例、平台能力与交互壳的职责边界；补充 ADR 0004
- 后续实现：同日 [ADR 0008](0008-native-macos-desktop.md) 将网页壳替换为原生壳，保留本记录的用例隔离。

## 背景

用户希望以游戏画面和状态为后续基础，并指出取点、截图、裁图和坐标配置成本较高。
本轮要求先把选窗、截取和裁图从脚本执行中分离，为新的 UI 壳提供独立能力。

这些交互需要桌面与文件系统，但无需读取脚本或运行步骤。把实现放进 runner 或
运行控制应用会让素材准备依赖脚本目录，也使未来更换 UI 或使用图片替身更困难。

## 决定

采用三层分工：

| 层 | 职责 | 当前实现 |
| --- | --- | --- |
| 准备 UI | 应用与窗口选择、冻结图像展示、点击和框选、名称输入与错误提示 | 当前为 `native/StarDesktop`，早期网页壳已移除 |
| 准备用例 | 冻结帧身份、取点坐标转换、裁图边界与操作编排 | `portable/preparation/` |
| 平台 adapter | 实际窗口查询与激活、截图、Pillow 裁图和模板落盘 | `platform/*/adapters/` |

脚本执行保持独立：`ScriptRunner` 不调用准备 UI 或准备会话，准备服务也不调用
runner、脚本目录、运行控制台或状态驱动流程。CLI/UI 可以调用各自用例，公共
几何模型与底层截图坐标转换可共享。

新增 `star --workspace PATH prepare` 作为准备入口。初版使用独立网页壳；该载体
已按 ADR 0008 替换为同一原生壳中的准备页面。准备服务本身没有运行脚本接口，
原生后台分别分发准备与运行请求。一个服务绑定一个显式素材工作区，模板保存在
该根的 `assets/`，不创建或改写业务脚本。

一帧包含唯一 ID、采集时间、窗口逻辑范围、PNG 与实际像素尺寸。点击、裁图必须
指向同一冻结帧。服务只保留一帧，新捕获使旧 ID 失效；捕获失败也不继续使用旧帧。
UI 把显示坐标转换为图像像素，准备用例再把像素点转换为窗口相对点及屏幕点。

准备截图与运行识图共享 `screen_capture.py` 的每轴像素比例转换。裁图只处理
冻结 PNG，不重新截图；保存时拒绝越界、路径名称和文件覆盖。

准备壳的选窗只属于素材会话，不隐式改变运行目标。当前运行仍显式传递
`--target-app/--target-window-title`；窗口相对点须配合相同目标窗口使用。
准备截图也不作为运行时可信状态缓存。

## 当前范围与代价

- 先提供手动截图、取点和模板保存；持续采集、实时状态流、录屏回放、完整编辑器及
  状态驱动的动作验证不属于本轮已实现能力。
- 真实截图当前覆盖主屏幕内的 macOS 窗口，超出范围明确报错；其他显示器与窗口被
  遮挡的捕获能力需要独立验证和后续平台实现。
- 窗口候选使用临时 AX 序号与标题指纹，捕获时重新核对；窗口消失、顺序或标题变化
  时需刷新列表，同一进程的重复标题不进行歧义 Raise。
- 只保留一帧，其他页面发起截图会使旧页面的框选失效；返回明确冲突并要求重截。
- 两个用例由同一原生壳组合，保持服务依赖方向不变，生命周期由 ADR 0008 定义。
- Linux 可通过替身保护逻辑、图像与 HTTP 契约，真实 macOS 权限、焦点与截图仍需实测。

## 与先前决定的关系

[ADR 0004](0004-small-console.md) 的运行控制台范围继续保留；其“截图和裁图工具不在当前产品中”
这一范围判断由本次用户要求调整为独立素材准备壳。旧调试路由不恢复。
[ADR 0006](0006-local-task-workspaces.md) 的业务素材归属保持不变。
