# 0015 统一使用 Python 任务函数

- 状态为 accepted
- 日期为 2026-11-14，用户明确要求清理旧格式并把全部脚本迁移为 Python 写法

## 背景

[ADR 0013](0013-function-tasks.md) 引入直接执行的任务函数，[ADR 0014](0014-core-first-execution.md) 将 `TaskContext` 独立为执行核心。此前保留的 JSON 任务和 Python 步骤树需要额外的解析器、解释器、条件对象、递归分析和示例注册。用户要求完成迁移并删除这些部分。

## 决定

工作区和通用示例统一使用 `.py` 文件，包含字面量 `TASK` 和同步 `run(ctx)`。函数、分支、循环和局部异常处理由 Python 表达。发现阶段通过 AST 读取声明，执行阶段使用主文件源码快照。

迁移全部活动工作区的任务和主仓通用示例。历史证据中的旧文件按历史记录保存。状态、窗口规则和素材资源配置继续由各自模块读取 JSON。

迁移调用方后删除 `Script`、动作与控制节点、条件对象、步骤解释器、条件评估器、JSON 任务解析器和内置步骤树示例。依赖分析只读取任务声明，任务详情展示入口、依赖与实际运行日志。

遗留 `.json` 任务放在 `scripts/` 中时显示迁移提示，其他有效任务仍可加载。目标窗口、资源、平台端口、准备服务和运行会话保持各自的职责。

## 迁移中的行为取舍

任务名称、目标声明、资源、动作顺序和循环次数按原任务迁移。需要在等待过程中退出的循环使用 `ctx.scope(checkpoint=...)`，由任务自己的函数判断画面并退出所属流程。有效任务预算使用期限作用域，只捕获本层 `scope_id`，外层期限继续传播。

函数正常返回为 `completed`，未捕获的等待超时为 `timed_out`，必需图片缺失为 `stopped_unmet_condition`。旧解释器把有限等待超时映射为退出码 0 的行为随迁移退役，任务可通过显式异常处理选择局部恢复。

依赖检查以声明为准。动态使用的共享点位、图片、搜索、状态与取色能力需要在 `requires` 中列出，本地资源自动纳入检查。无法从动态控制流生成完整静态步骤预览，实际动作通过运行事件查看。

## 验证与代价

自动化验证执行核心、静态发现、坏文件隔离、依赖、CLI、原生后台协议和资源清理。迁移任务使用受控画面与虚拟时钟回放，核对主要分支、循环退出、期限和取消。

真实游戏验收继续由工作区记录。迁移通过和 `completed` 均须结合目标应用中的证据判断业务完成。开发应用绑定具体 checkout，加载新任务需要使用包含本次迁移的框架版本。
