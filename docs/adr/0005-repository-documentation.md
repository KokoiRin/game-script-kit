# 0005：以仓库文档保存上下文和决策

- 状态：accepted
- 日期：2026-10-18（用户明确确认整理仓库文档并移除 OpenSpec 目录）
- 性质：文档职责与历史资料边界

## 背景

OpenSpec 退出开发流程后，历史提案曾继续留在工作区。当前上下文与设计取舍已迁入仓库文档，旧目录继续增加查找成本，也容易让已删除能力和旧路径重新进入实现。用户确认直接删除目录，需要旧资料时查询 Git 历史。

本轮需要留下重新确认的目标、架构理由、真实能力差距和未定方案，方便下一次从准确状态继续；不需要重新建立一套提案生成与校验流程。

## 决定

从工作区移除整个 `openspec/`，包括旧规格、提案、任务清单和工具配置。历史通过 Git 查询，不在工作区维护副本；新需求不创建 change、同步 delta 或执行 OpenSpec 校验。历史描述与当前需求不一致时，核对当前代码、测试和用户确认，不据旧规格恢复功能。

文档各自承担明确职责：

- [AGENTS](../../AGENTS.md) 保存开发操作约定；[CONTEXT](../../CONTEXT.md) 保存目标、领域语言和协作上下文。
- [架构约束](../architecture.md) 保存稳定边界；[ADR](README.md) 保存重要决定、理由和代价。
- [当前状态](../current-state.md) 保存已实现能力、验证范围和欠账；[重启计划](../restart-plan.md) 保存后续建议。
- `docs/design/` 保存待讨论方案，显式标注未采纳、未实现；[文档导航](../README.md) 负责阅读入口。

这些文档不要求每次改动全部更新。只更新本次行为或决定实际影响的事实；小修不强制新增 ADR，讨论稿也不自动转化为实现门禁。

具体任务的玩法、脚本维护记录和运行证据归入外部本地工作区，主仓文档范围按 [ADR 0006](0006-local-task-workspaces.md) 保持为框架上下文。

## 代价

- 需要人工保持当前事实、已采纳决定和讨论建议之间的区分。
- 同一条规则尽量维护一份正文并交叉引用，避免复制成多处容易漂移的规范。
- 查阅旧规格需要指定历史提交；Git 保留原记录，删除工作区副本不压缩 Git 历史。

## 重审条件

当文档重复、相互冲突或查找成本持续阻碍工作时，先调整职责与导航；只有出现实际协作需求时，才考虑额外工具和流程。
