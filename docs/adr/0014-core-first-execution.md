函数任务接入后，上下文仍需操作旧解释器的私有期限状态。资源分析与能力分析重复理解输入，目录错误隔离和原生停止确认也存在多处所有者。本轮将核心规则集中到直接运行上下文，再以各自拥有实际职责的 adapter 接入任务格式与平台。

## 决定与代价

`TaskContext` 直接执行定位、输入、等待、期限、取消和事件，核心使用窗口、命名资源及已打开的运行能力。旧步骤树控制流集中在兼容 adapter，函数任务直接调用上下文。

操作结果和作用域期限具有各自身份。输入提交及恢复由原生窗口会话维护，任务执行和资源关闭由应用用例管理。工作区目录拥有格式无关的发现与错误隔离，任务分析为依赖、详情和能力需求提供相同事实。

比较的命令推进方案需要额外维护命令、请求、回复、续态和 driver。直接上下文保持当前 Python 调用方式，使作者和测试跨同一 interface。核心内部承担更多规则，以提高 depth 和 locality。

原生会话保留实际运行占用，同时记录用户停止意图。停止中显式重启使用已有关闭监督和实际退出确认，再启动新代次。

这项决定调整 [ADR 0013](0013-function-tasks.md) 的执行实现和兼容方式，保留其函数任务格式、静态发现与现有工作区的迁移约定。整体职责图和接入顺序见 [核心优先设计](../design/core-first-execution.md)。
