# 0011：窗口状态按优先级分组截断

- 状态：accepted
- 日期：2026-11-06
- 来源：用户要求对话命中后跳过低优先级状态，减少无效匹配并避免主页竞争。

## 决定

窗口规则在 `groups[].priority` 配置整数，数值越大越先检查，缺省为0。同一状态的多个组必须具有一致优先级。相同优先级组先完成全部素材匹配，再按原相似度规则选候选。某层命中后不加载或匹配更低层的模板。全部未命中则检查全部候选。

优先级只在窗口观察用例启用。旧 `screen-states.json` 及脚本reader原有首次命中行为保持不变。通用批量图像请求携带执行优先级，匹配器通过显式开关启用按层截断；不能同时开启首次命中截断。一次调用只获取一张截图。模板路径按需转换一次整窗数组，纯多点路径不转换整窗数组，结果按原候选顺序返回。

每轮从最高层开始，不因上一轮状态跳过高层。截断不等待连续确认，高层命中但尚未确认时当前状态保持未知，不再计算主页。源时间、重复证据与停止屏障保持原契约。

低层结果标为skipped，协议与UI显示未检测，分数和坐标为空，不复用旧证据。性能面板分别显示配置素材数、最近完成轮实际检查数及跳过数。保存同状态新素材默认继承已有优先级，新状态默认0；显式优先级在写素材前校验。

## 边界

游戏中的层级数值由外部工作区配置，不在框架硬编码。当前只输出一个优先处理状态，不证明被跳过层不存在。无命中场景仍有全量匹配成本，后续可依据任务需要限制候选范围。本轮不实现组合状态或观察结果驱动输入。

## 验证

自动化覆盖同层比较、跨层截断、下探、旧配置默认值、非法与冲突优先级、保存继承、跳过模板不读取、一次截图和整窗转换、协议检查数量及确认阶段不降级。真实平台验收由本轮根执行者另行记录。


## 2026-11-07 多点匹配补充

用户要求把六种固定布局场景改为多点颜色识别。窗口搜索项新增 `method: "points"`，旧配置缺省仍为 `template`。`points` 是2到64个不重复点组成的数组，每个点包含整数像素 `x`、`y`、三个整数通道的 `rgb` 和可选 `tolerance`。RGB范围0到255，容差范围0到100，默认35。`offset_radius` 默认1，范围0到2，单位也是截图像素。坐标相对完整采集截图，不是屏幕全局坐标或窗口逻辑点。

一次判断在同一张图像中直接读取点位。允许整组共同平移，所有点的所有通道都落入各自容差才命中，不允许各点分别寻找附近颜色。窗口逻辑尺寸和完整截图像素尺寸仍须与采集时一致，移动窗口不改变点位。状态优先级、同层全部检查、低层截断及源时效和停止屏障保持原规则。纯多点路径不加载OpenCV、不转换整窗数组；只有实际执行到模板请求时才加载模板依赖。

多点配置保留 `image` 作为参考素材身份，当前加载器仍要求参考PNG存在。运行匹配阶段不读取该PNG像素。`region` 与 `min_confidence` 只影响模板方法，不会放宽多点的全点要求。多点失败证据显示最佳共同偏移下通过的点数，不能将通过比例理解为统计置信度。命中多点的内部排序分数为1，同层多个多点都命中时沿用配置顺序；同层混合模板时，仍沿用最高分语义，因此全点命中优先于小于1的模板分数。游戏应通过有区分度的点位和优先级避免依赖跨方法分数比较。

点位属于外部任务工作区，不在框架硬编码。本次六场景各8点是工作区选择，不是框架固定点数。普通素材准备入口仍登记模板，点位目前由Agent观察并写入规则文件。UI列出多点数量和整体偏移，匹配证据显示实际通过点数；未检测项不携带已匹配点数。
