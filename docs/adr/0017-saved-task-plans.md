# 0017 保存并运行有序任务流程

- 状态为 accepted
- 日期为 2026-11-15，用户要求串联已有日常任务、在指定任务结束后等待，并允许活动不可用时返回主页后跳过

## 决定

工作区 `.star/run-plan.json` 保存一套流程的名称、有序任务引用及各项 `wait_after_seconds`。任务主体继续使用 Python `TASK` 与 `run(ctx)`，流程引用 catalog 中的任务名称。主仓提供通用编排，具体任务顺序与等待时长保存在外部工作区。

CLI `run-plan --saved` 与原生运行页共用计划用例。桌面整套流程复用单任务的后台线程、运行槽、日志与停止信号。启动前解析全部任务引用和资源别名，每个任务独立开启并关闭原生窗口会话。任务正常完成后的等待发生在窗口会话关闭之后，以实际经过时间计时，停止请求可以中断等待。模拟模式直接略过实际等待时长。

任务通过 `TaskSkipped` 明确表示已完成收尾并可继续后续任务，映射为 `0/skipped`。计划保存该结果并继续，跳过项的任务后等待也随之略过。任务的画面判断和返回起点由工作区 Python 流程负责。其他错误沿用停止策略，取消和清理失败终止整套流程。

## 代价与重审条件

当前每个工作区保存一套可由 Agent 编辑的流程，原生页提供选择、查看顺序、启动和停止。需要多套流程或交互式调整顺序时，沿已有配置与用例扩展。各任务仍负责满足下一任务的起点要求，新的恢复策略依据具体画面和失败证据决定。
