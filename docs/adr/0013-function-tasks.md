# 0013 直接执行 Python 任务函数

- 状态为 superseded，由 [ADR 0015](0015-python-only-tasks.md) 完成统一迁移并退役旧格式
- 日期为 2026-11-14，用户授权基于现有原生实现创建分支并重构任务基础

执行核心与兼容方式随后按 [ADR 0014](0014-core-first-execution.md) 调整。本文保留函数任务格式与静态发现的选择依据。

## 背景

任务主要由 Agent 编写。嵌套 JSON 在秘境接续等流程中出现空动作占位，局部缺图和超时难以处理。现有内置 Python 示例构造相同步骤树，表达能力继续受解释器限制。

任务运行已经具有固定窗口、后台输入、暂停恢复、任务时钟和日志。这些能力继续由一次应用运行会话持有。

## 决定

新增独立 `FunctionTask`，保存元信息、声明依赖和主文件源码快照，与既有 `Script` 组成明确的任务输入变体。Python 文件中的 `TASK` 使用字面量，发现阶段通过 AST 读取。运行时执行同步 `run(ctx)`，函数自行组织分支、循环、返回值和局部恢复。

共享 `ActionRuntime` 承接原子动作、定位、窗口坐标、输入提交、轮询和动作事件。旧步骤解释器与新的 `TaskContext` 使用同一份实现。应用用例统一打开和关闭原生运行时，CLI 与原生协议复用该用例。

局部超时使用 `TaskTimeout`，必需图片缺失使用 `TargetNotFound`，用户取消使用独立的终止信号。线程局部 tracing 仅检查任务代码的用户取消，恢复性超时在上下文调用边界检查。该选择避免任务捕获超时后失去 tracing。

## 方案选择

本轮比较了独立 `FunctionTask | Script` 和统一程序包装两种设计。选择前者，直接复用当前元信息访问及运行装配。采纳显式期限作用域和按任务目录检查取消的建议。

统一程序包装会增加旧 `Script` 转换和兼容入口。把 callable 加到现有步骤树会继续混合静态树与动态函数。工作进程和动作通信能够扩大强制停止范围，同时增加平台资源所有权与进程清理协议。本轮采用线程内执行，并验证纯 Python 循环停止。

同模型独立设计审查核对了现有调用方、资源声明和 tracing 关闭行为。完整动态步骤预览让位于声明依赖与实际运行事件。

## 清理范围

已将 runner 中的原子输入、目标解析和动作事件迁入共享内核，删除其原位置实现。资源解析与 readiness 在新旧任务间共用。

| 后续可删除部分 | 删除条件 |
| --- | --- |
| JSON 步骤语法解析 | 外部工作区的 JSON 任务完成迁移 |
| `Repeat`、`If`、`WaitUntil` 控制节点及解释器 | 旧任务和内置示例完成迁移 |
| 步骤树递归依赖推导与摘要生成 | 全部调用方改用函数声明与实际动作事件 |
| 旧条件对象及 `evaluate_condition` | 旧条件调用方和状态参数校验完成迁移 |
| 内置步骤树示例注册和导出 | 相关示例与测试调用方改用函数任务 |

资源目录、目标窗口、图像查询、平台端口、准备服务、运行会话和结果归一化仍各自承担独立职责。当前业务工作区继续使用已有 JSON，迁移以实际流程的停止、恢复和完成证据为验收条件。

## 验证

自动化覆盖 Python 控制流、静态发现、声明资源、局部失败、期限、取消和原生后台协议。平台动作通过 fake 验证单次会话和输入边界。真实游戏任务迁移与实机验收另行记录。
