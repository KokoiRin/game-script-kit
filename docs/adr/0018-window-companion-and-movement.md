# 0018：控制台贴右跟随与运行中窗口平移

- 状态 accepted
- 日期 2026-11-15，用户确认固定尺寸、始终贴右和运行中移动后继续

## 背景

游戏窗口尺寸固定。用户希望点击游戏时一起显示控制台，拖动时保持两个窗口紧贴。旧会话把原始完整矩形作为恢复条件，平移后需要精确还原原点，无法满足日常拖动。

## 决定

运行继续绑定同一 PID、CGWindowID、标题和素材尺寸。原点可以改变。每次有限输入准备或观察固定一份几何快照，点位、ROI、截图解释和结果转换共用它。操作途中平移时丢弃未提交的准备或观察，等待新画面后重新执行。外层任务函数及长等待继续原有控制流。

输入尝试按下后进入已提交阶段。移动、取消或失败时尝试释放同一窗口内锚点，后续操作采用新位置。已提交输入不会重放。恢复等待从有效任务时间扣除，并可取消。后台后端在尺寸变化、隐藏和暂缺画面时等待原窗口展示恢复。前台后端对纯平移采用新位置，其他展示故障沿用原有立即报告行为。身份失效继续报错。

原生控制器独立读取窗口元数据，以控制台左边贴目标右边、顶部对齐计算布局。允许窗口越过屏幕边缘。游戏激活或被点击时，控制台使用非激活排序恢复显示，保留游戏键盘焦点。原生布局采样不参与运行坐标同步。

跟随目标通过 `companion.target` 提供。空闲时采用选中任务或保存流程的唯一目标，默认观察页采用工作区唯一共同声明。多个不同目标时保持未绑定。选窗规则与实际运行共用一个平台解析函数。运行中只发布实际已打开会话的 PID 与窗口编号，关闭会话后撤销活动绑定。整套流程的任务后等待沿用本次已验证身份供窗口跟随，流程结束或新运行开始时清空。准备页选窗继续独立管理。

## 代价

macOS 端口继续沿用全局坐标合同，平台内部必须保证有限操作快照覆盖完整转换。新增观察能力需要接入同一边界。返回任务的图像匹配结果仍表示当次观察，跨操作缓存结果保留历史坐标语义。

原生跟随使用轻量元数据采样和应用激活通知。不同 Space、全屏、系统动画及特定游戏的事件接收仍需要相应真实设备验证。
