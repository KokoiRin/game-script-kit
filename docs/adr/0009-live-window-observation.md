# 0009：原生界面中的只读窗口状态观察

- 状态：accepted
- 日期：2026-11-05
- 来源：用户要求把实时状态识别接入原生 UI，保留素材准备与执行的边界。

## 背景

手动截图已经可用，但准备帧只代表采集时刻。任务需要观察正在变化的窗口，并查看每条素材的识别证据。持续采集不能复用会切换焦点的手动准备入口，也不能把 UI 中显示的旧状态直接用作脚本条件。

## 决定

原生壳新增“实时识别”页。用户在素材准备页登记状态素材及搜索范围，在识别页选择目标窗口、频率及连续确认方式，启动或停止观察。

应用层的观察会话独立于准备服务和脚本执行。一个采样线程拥有自己的探测器与临时图像，串行处理最新一帧。原生壳限流读取状态快照，负责显示和后台进程监督。暂不把观察快照接入 runner，也不在观察中执行输入。

每个快照包含明确阶段、已确认状态、本帧候选、序号、采集时间、耗时、识别证据和有界历史。取消先撤销当前状态，再等待采样资源回收。停止后完成的旧采样不能恢复有效状态。新鲜度使用单调时钟，窗口流以系统源事件时间判定，旧请求式探测以采集开始时间下界判定；首帧未到达和过期帧均不输出已知状态。窗口流与连续独立确认的后续取舍见[ADR 0010](0010-window-stream-observation.md)。

只读观察使用目标窗口编号采集，不反复激活游戏。每轮一张图，所有候选使用同一帧。窗口身份和采集几何变化必须给出可见错误。慢帧不排队补跑。采样线程卡住时，原生壳复用既有后台退出、终止和强制回收路径，实际退出前保留停止中。

## 素材与坐标

窗口观察规则写入所选工作区的 `assets/window-states.json`。沿用旧候选解析和批量匹配能力，但不改变 `screen-states.json` 的屏幕坐标语义。

模板保存截图像素。搜索范围保存窗口内逻辑坐标，登记时从冻结帧像素转换。规则同时绑定窗口逻辑尺寸与完整截图像素尺寸。窗口移动不会改变相对区域，尺寸或显示缩放不匹配时要求重新校准。

模板文件排他创建，配置用临时文件原子替换。配置登记失败只回滚本次新素材，不覆盖已有用户文件。采样中的素材配置保持不变，需停止后登记或重新加载。

## 当前识别语义

每条素材是一个状态候选。当前结果采用本轮达到阈值的最高匹配分数，再按用户选择连续确认。同状态的多份素材是可替代候选，不表示需要全部命中。多证据组合、同时存在的主状态与覆盖层以及观察结果驱动任务，留待具体任务验证后扩展。

相似度是模板匹配分数，不是识别正确率。未命中、窗口不可用、过期和停止必须分别可见，均不能当作已知游戏状态。

## 取舍

选择进程内单采样线程，复用现有原生进程监督。独立观察子进程能更细地回收识图，但增加解释器、IPC、捕获实现及权限验证范围，本轮不采用。设计比较与验证记录保留在本次本地工程记录中。

## 窄版观察与性能证据

原生观察默认使用屏幕右侧窄窗，素材准备及脚本运行保持宽版。置顶只影响 Star 自身窗口，不激活或调整游戏。

性能数据属于应用层不可变观察快照，以实际完成采样为单位累加。采样线程发布证据和统计共用取消屏障。阶段耗时由 probe 提供可选的类型化元数据；后台没有阶段信息时不伪造零值。分位窗口最多120轮，停止保留本次统计，新会话清空；指标口径与离线基准边界见[原生说明](../../native/StarDesktop/README.md#性能监测与素材规模)。

## 验证

自动化覆盖采样取消、首帧与慢帧、新鲜度、窗口身份、缩放、素材事务和协议互斥。最终以实际原生 UI 的登记、读回、观察和停止闭环为准。最新结果见 [当前状态](../current-state.md)。
