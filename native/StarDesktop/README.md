# Star macOS 原生壳

使用 macOS 13+ 的 SwiftUI 和 AppKit，SwiftPM 不包含任何第三方 UI 包。
Python 核心运行在受壳管理的独立进程中；不启动浏览器或本地 Web 服务。

## 开发环境

在 Mac 安装 Xcode 或 Command Line Tools（Swift 5.9+），然后在仓库根目录准备 Python：

```bash
python3.14 -m venv .venv
.venv/bin/python -m pip install -e '.[dev,macos]'
swift build --package-path native/StarDesktop
mkdir -p ~/StarWorkspaces/my-tasks
.venv/bin/star --workspace ~/StarWorkspaces/my-tasks ui
```

也可使用 `.venv/bin/star-desktop`，首次在原生目录选择器选择任务根。需要进入
运行页时可使用 `star-desktop --workspace PATH --tab run`。
当前工作区下的 `.star/desktop.log` 保存后台与会话诊断。

## Finder 应用

在仓库根目录执行：

```bash
.venv/bin/python tools/build_macos_app.py
open native/StarDesktop/dist/Star.app
```

使用 `--install` 可将应用放到 `~/Applications/Star.app`，不必从临时目录手工找文件：

```bash
.venv/bin/python tools/build_macos_app.py --install
open ~/Applications/Star.app
```

如果本机 SwiftPM 无法编译 manifest，可显式选择 `--compiler swiftc --install`。
直接编译会固定 `arm64/x86_64-apple-macosx13.0` 目标，不继承编译器过高的默认目标。
构建错误会明确失败，不静默切换编译方式。

开发版 Info.plist 绑定构建时的仓库路径和 Python 解释器；移动仓库或重建环境后
重新构建应用。当前未打包 Python、进行发布签名或公证，不能当作独立发行版。

### 保留重建后的授权

日常开发应使用固定的本机代码签名身份。临时签名的身份随内容变化，可能出现系统设置开关已开、更新后的后台却无权限的情况。
构建身份按 `--signing-identity`、`STAR_SIGNING_IDENTITY`、`~/Library/Application Support/Star/signing/identity` 的顺序选择；未配置时使用临时签名并明确警告。配置文件只保存既有证书的 40 位 SHA-1 指纹，不保存私钥。

已有受信任的本机代码签名证书时，可以先用 `security find-identity -v -p codesigning` 确认，然后构建：

```bash
.venv/bin/python tools/build_macos_app.py --compiler swiftc --install --signing-identity YOUR_CERTIFICATE_SHA1 --verify-signing
```

也可将该指纹单独保存到上述 Star 身份文件，让后续普通构建自动复用。工具不会自动创建证书、导入私钥或修改钥匙串信任；显式配置错误、签名或校验失败会停止，不降级成临时签名，也不替换原安装。
`--verify-signing` 修改并重签临时副本，检查内容哈希变化后仍满足原版本的证书身份要求；不启动副本或操作系统权限。

首次从临时签名迁移到固定证书，仍需为固定位置 `~/Applications/Star.app` 重新登记一次窗口控制和截图权限。后续保持应用标识、证书和启动链路稳定；保留证书及钥匙串私钥，不重新生成身份。系统策略或目标链路改变时仍需重新核对，签名验证本身不证明权限已经授予。
如果系统开关已经开启、后台仍显示未授权，应先核对是否保留了旧预览版的授权。
本机从临时预览迁移到安装版时，TCC 日志实际报告旧代码签名要求不匹配；
需要用户在系统设置中移除旧 Star 项，再添加当前 `~/Applications/Star.app` 并确认授权。
仅重启后台不能修复旧签名记录；不要通过重置其他应用的权限或修改系统权限数据库处理。
也可用 `STAR_PYTHON`、`STAR_SOURCE_ROOT` 指定开发环境。

## 首次授权

顶部“系统权限”检查实际 Python 后台的权限，不以原生壳进程的状态代替它：

- “窗口控制”用于读取和激活应用窗口。在系统设置中旧名为“辅助功能”，部分系统版本显示“设备控制和数据访问”。
- “屏幕截图”用于截取目标画面，对应“录屏与系统录音”。
- 点击对应的申请按钮才调用系统申请接口；辅助功能申请是异步提示，返回成功响应不等于用户已经批准。
- 从系统设置返回后自动重新检测，也可点“重新检测”。系统尚未更新进程权限时，可点“重启后台”后重试。
- 系统提示的授权对象以实际启动链路为准，推荐从固定位置的 `Star.app` 打开。构建、普通查询和模拟运行不会自动申请权限。
- 运行脚本期间禁用权限申请。用户拒绝或尚未批准时显示缺少的权限，不重复执行读取、截图或脚本。

原生管道按当前可用字节读取。不能用固定长度读取等待短 JSON 响应，否则启动握手会等到超时。
后台在管道请求到达后处理 macOS 主运行循环中的应用状态通知，保证先打开 Star、后打开目标应用时仍能查询到新窗口，不需要为此手动重启后台。

## 登记素材并开始实时识别

实时识别和脚本运行页使用靠屏幕右侧的窄窗口，约 520×820 点，可以与游戏并排。顶部切换页面，素材准备页自动展开为宽窗口，回到运行或识别页时恢复窄布局。运行页的脚本选择和运行控制分行排列，依赖与日志支持换行。“置顶”调整 Star 的窗口层级，窗口按当前屏幕可用范围放置。

1. 选择游戏工作区，进入“素材准备”页，填写目标应用并读取窗口。
2. 截取画面。需要限制搜索范围时，先框选较大范围，点击“将框选设为搜索范围”。默认搜索整个窗口。
3. 再框选小素材，填写素材名、它代表的状态和匹配阈值，点击“保存状态素材”。
4. 进入“实时识别”页。确认目标窗口，选择每秒 1、2 或 5 次检测，点击“开始观察”。默认每秒 2 次、连续两次独立源证据确认。
5. 查看当前状态、本帧候选、每份素材的匹配分数和坐标、画面时效及状态变化。展开“性能”查看采样成本。
6. 点击“停止观察”。停止后当前状态失效，等待资源回收后可以继续登记素材或运行脚本。

实时观察需要macOS14+及macos可选依赖。采集频率跟随每秒1/2/5次检测，默认2次；没有更高的隐藏帧率。窗口流只保留最新画面，系统明确未变化且带新源时间的idle也可确认；重复缓存不增加确认也不续期。每轮所有素材共用同一帧，不发送输入。检测耗时超过间隔时不积压采样。窗口关闭、身份或采集几何变化、截图失败和画面过期时显示错误或未知，不沿用旧的已知状态。后台回收以实际退出为准。

状态模板写入工作区 `assets/`，窗口规则、状态和共享搜索写入 `assets/window-states.json`。窗口规则绑定采集时的逻辑尺寸与截图像素尺寸，改变窗口大小或显示缩放后需重新校准。

当前观察页显示文字证据，不是实时视频。观察 UI 缓存只用于展示，不驱动动作；原生脚本通过独立运行会话复用同一窗口规则，读取自己的实时画面。每条素材需在应命中和不应命中的画面上分别验证。

## 性能监测与素材规模

“性能”按后台实际完成的采样轮次统计，不按 UI 轮询次数统计。显示当前素材数量、最近完成轮的截图/识别/整轮耗时，累计完成轮数、失败、超频率预算及超龄结果；最近最多 120 轮的 p50/p95/最大值包含失败尝试。未命中“未知”不算采集失败，尚未完成的卡住采样也不计成已完成轮。停止保留本次统计，开始新观察重置。

窗口流取帧阶段包括窗口核对、内存转RGB和像素校验，首轮还包括启动等待；不再每轮运行截图命令或读PNG。源画面年龄p95及重复读取独立显示，源时间来自系统事件，经单调时钟映射；快速读取不意味着画面同样新。模板识别阶段包括 OpenCV 冷加载、图像数组转换、模板读取/缓存、区域处理和匹配。纯多点识别阶段直接检查固定像素，不执行这些模板处理。整轮不含调频等待、协议传输或 UI 显示延迟，因此不等于点击到确认新状态的总延迟。冷启动首轮可能更慢；缺少阶段数据时显示“—”，不猜测为零。频率预算为每秒 2 次时 500 ms、每秒 5 次时 200 ms；慢帧不积压补跑。

每条新素材应登记状态、稳定模板、窗口相对搜索范围和适用尺寸，并在出现与未出现的画面分别检查证据。所有素材共用同一帧，但每条搜索仍有成本；优先收紧搜索范围，再依据实测超预算次数决定是否降低频率或拆分候选。窗口规则按优先级分层检查，命中后跳过低层；同层素材仍全部检查。

可对保存的完整来源帧做只读负载对比：

```bash
PYTHONPATH=src .venv/bin/python tools/benchmark_observation.py \
  --workspace /path/to/workspace --frame /path/to/source.png \
  --counts 2,10,50,100 --iterations 20 --output /private/tmp/observation-benchmark.json
```

工具不采集屏幕或发送输入，不写素材；比较已配置 ROI 与全窗口搜索。循环重复已登记请求只是合成负载，不代表相同数量的不同真实模板。JSON 分开记录进程首轮冷加载、各 case 首轮及随后成功轮的分位数、完成请求数与失败。离线结果包含内存图转换与识别成本，不含真实截图或磁盘帧解码，不能作为实机全流程耗时。

## 职责

- `Main.swift`：原生窗口、菜单、工作区选择与统一退出路径。
- `Session.swift`：后台监督、请求超时、管道与日志回收、单帧缓存。
- `WorkspaceView.swift`：素材准备与脚本运行界面。
- `Canvas.swift`：原生截图画布、像素取点及框选，不解释脚本。
- Python `desktop_backend.py`：串行协议分发、后台执行会话、文件锁与临时 PNG。

运行中禁止截取新画面或重复启动脚本。关闭时先请求取消、等待线程结束；平台
调用无响应才使用有界的进程回收，不重放动作。详细边界见 [ADR 0008](../../docs/adr/0008-native-macos-desktop.md)。

停止脚本后，运行页保持停止等待状态，确认结束后释放运行占用。等待期间可显式点击“重启后台”，沿同一关闭监督流程回收旧后台，再启动空闲的新后台。重启期间退出应用会撤销待重启请求，关闭完成时后台保持退出。任务等待超时与资源回收失败分别显示对应中文结果。

## 验收

云端原始提交只验证了 Python 部分与 Swift 语法；本机接续另行记录 SDK 编译和界面验证，不能据此推定全部桌面功能已验收。
`.github/workflows/macos-native.yml` 包含 Mac 构建检查，需在推送后实际运行。
回到 Mac 后先构建，再检查工作区切换、取点和裁图、模拟运行、运行中关闭窗口、
Command+Q、后台意外退出，以及辅助功能和屏幕录制权限。授权对象以系统弹窗为准。

## 状态优先级

窗口规则 `assets/window-states.json` 的每个状态组可设置整数 `priority`，默认0。数值较大的层先检查，同层全部匹配，命中后跳过更低层。未检测素材显示“未检测”，不当作未命中，也不沿用旧证据。性能面板显示本轮检查和跳过数量。新增同状态素材继承优先级；旧配置全为同层，维持原最高分选择。旧脚本屏幕状态reader不受此设置影响，完整取舍见[ADR 0011](../../docs/adr/0011-priority-window-observation.md)。


## 固定布局的多点识别

Agent可以在工作区 `assets/window-states.json` 的搜索项中设置 `method: "points"`，并登记截图像素坐标、RGB及逐通道容差。全部点在同一个共同偏移下满足容差才命中。原生控制台显示“多点”和实际匹配点数，素材列表显示点数及整体偏移范围。点位不随窗口在屏幕上的移动改变，窗口或显示缩放尺寸变化仍会使观察失效。

每组允许2到64点，`offset_radius` 默认1截图像素，最多2。原有PNG作为参考仍需保留，实际多点匹配不读取模板图像。多点不使用模板的搜索区域或最低相似度。旧规则和普通准备页保存的素材继续使用模板识别。完整格式及同层排序限制见 [ADR 0011](../../docs/adr/0011-priority-window-observation.md#2026-11-07-多点匹配补充)。


## 运行固定窗口脚本

准备页选窗不会修改脚本的运行目标。Python 任务在 `TASK` 中声明 `target`，省略 `backend` 使用桌面实现，显式原生模式使用同一窗口完成截图、取色、模板和状态判断。

```python
TASK = {
    "name": "窗口任务",
    "target": {
        "application": "目标应用",
        "window_title": "完整窗口标题",
        "width": 800,
        "height": 600,
        "backend": "macos-window",
    },
}
```

尺寸应填写素材采集时的实际逻辑尺寸，工作区须已有 `assets/window-states.json` 的逻辑和像素尺寸配置。原生模式不接受 CLI 目标覆盖。每次运行重新绑定当前窗口位置，前台模式运行期间移动、缩放、关闭或替换窗口会停止，后台模式的短暂变化按下述规则等待恢复；输入后等待新的系统画面再确认状态。

先停止观察，在运行页重新加载脚本，完成模拟后再运行真实模式。观察会话与脚本会话不共享截图缓存或连续确认历史。日志显示实际 backend、PID、窗口编号及固定矩形；“点击完成”本身不证明目标已经响应。

### 前台模式

`macos-window` 固定使用 `foreground-session` 原生输入。必要时对绑定 PID 请求 AX 前台状态，每次发送前核对真实前台 PID，鼠标按下前检查点位最上层可见窗口仍为目标。只精确排除系统光标层，其他可见浮层遮挡会停止；按键还会核对绑定进程的焦点窗口。

### 显式后台点击试验

仅在任务明确选择试验时，将 `backend` 改为 `macos-window-background`。目标可以切到前台，点击仍投递到原 PID。该模式复用同一视觉会话，只支持点击与等待，不请求前台、不全局投递或移动真实指针，日志为 `input transport=background-pid-experiment`。

打开调度中心或窗口短暂变化时，任务会暂停点击，并在运行记录中显示原因。退出调度中心、恢复原窗口矩形后，取得新画面即可接续。尚未发送的图片点击会重新识别，暂停时间从任务时限扣除。若实际拖动或调整了窗口大小，需要恢复日志中的原始矩形，等待期间仍可点击“停止脚本”。

后台试验依赖私有系统函数 `CGEventSetWindowLocation`，缺失时明确失败，不自动切换输入方式。Star 自有 port 已在本机同桌面游戏的一次“主页→活动”短探针中由新画面确认状态转换，独立30秒采样的前台进程和指针位置未变；这不代表所有应用、跨桌面或长期运行已验收。后台按键与拖拽明确不支持。

两种原生模式均不承诺锁屏或跨桌面运行。停流失败显示 `cleanup_failed` 并保留进程级租约，需重启后台后再运行；用户取消仍优先且保留清理错误。完整边界见 [ADR 0012](../../docs/adr/0012-native-script-runtime.md)。
