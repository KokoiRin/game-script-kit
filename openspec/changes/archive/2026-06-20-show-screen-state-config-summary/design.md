## Context

`assets/screen-states.json` 已经是状态识别任务的配置来源，但目前 UI 只能读取状态名候选，无法展示搜索项细节。用户调试脚本前需要知道配置是否加载、图片是否正确、区域和阈值是否符合预期。

## Goals / Non-Goals

**Goals:**
- 复用现有配置解析边界，生成只读配置摘要。
- 通过 application 和 HTTP adapter 暴露摘要，前端只负责渲染。
- 让缺少配置和非法配置都有明确的 UI 状态。

**Non-Goals:**
- 不做配置编辑器。
- 不做截图裁剪、区域拖拽或素材采集。
- 不改变探测候选生成和图片匹配行为。

## Decisions

- 在 `screen_state_config` 中增加摘要数据结构和读取函数。配置语义仍集中在一个 module，避免 HTTP/UI 自己理解 JSON 结构。
- 摘要使用用户可读字段：状态、搜索名、图片相对路径、区域名或内联区域、最低置信度。真实探测仍使用已解析的候选对象。
- application 层把缺少配置表示为 exit code 0 的空摘要，把非法配置表示为非零结果和错误消息。这样 UI 可以区分“还没配置”和“配置坏了”。

## Risks / Trade-offs

- 摘要读取会和候选读取有部分解析逻辑重叠 → 通过复用底层解析 helper 控制重复，不在 UI 里复制 JSON 规则。
- 首版只读不能直接修配置 → 这是刻意限制，先让用户能看懂当前配置，再决定是否需要编辑器。
