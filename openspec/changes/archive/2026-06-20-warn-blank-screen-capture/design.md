## Context

当前截图诊断命令只判断截图 adapter 是否抛错。真实环境中，macOS 截图权限或远程会话异常可能让 adapter 成功返回一张纯黑图，后续状态探测、区域诊断和候选裁剪仍会继续执行，导致用户把问题误判为素材或区域配置错误。

## Goals / Non-Goals

**Goals:**

- 在 application 层保存截图后检查截图内容是否疑似全黑。
- 对截图诊断类用例返回用户可见警告，让 CLI/UI 现有展示链路自然显示该提示。
- 保持截图文件继续保存，便于用户查看和反馈。

**Non-Goals:**

- 不自动修复 macOS 权限或打开系统设置。
- 不改变图像匹配算法、截图 adapter 或状态选择规则。
- 不把所有低亮度截图都视为失败；本轮只识别明显纯黑或近似纯黑的异常截图。

## Decisions

- 在 `LocalControlApplication` 附近新增截图健康检查 helper，输入已保存图片路径，输出可选警告文本。
- 健康检查只依赖图片像素统计：当图像所有 RGB 通道最大值都低于很小阈值时，认为疑似全黑。
- 截图类用例仍返回原有 `exit_code`，但把警告写入 `ControlResult.stderr`。这样 CLI 会打印到 stderr，UI 日志也会展示，不会破坏已有成功路径和截图文件生成。
- helper 放在 application 层而不是 CLI/UI，因为 CLI/UI 不应该读取图片或解释截图诊断语义；adapter 也不适合判断截图是否“业务上可用”。

## Risks / Trade-offs

- 真实游戏画面如果处于纯黑加载页，也会触发警告。缓解方式是警告文案使用“疑似”，不把命令直接改成失败。
- 只检查全黑不能覆盖白屏、冻结画面或错屏。后续可扩展为更完整的截图诊断报告，但本轮先解决已经观察到的问题。
