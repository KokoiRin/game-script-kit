# Change: 真实脚本复用后台界面探测状态

## Why

Star 已经有两条状态相关链路：

- UI 可以启动后台界面探测，持续识别当前界面并展示给用户。
- 真实脚本遇到 `ScreenStateIs(...)` 时，会通过 `ScreenStateReader` 即时执行一轮状态探测。

这让“当前识别到的状态”仍然主要是 UI 展示信息，脚本判断没有优先使用这份已经识别出的状态。对梦幻西游这类画面状态变化较慢的游戏，用户已经启动界面探测后，脚本应该能更自然地参考这份当前状态，同时减少重复截图和匹配。

## What Changes

- 本地控制 application 的真实 `ScreenStateReader` 优先读取正在运行的后台界面探测状态。
- 只有后台探测正在运行且已有非 `未知` 状态时才复用缓存。
- 没有后台探测、后台探测已停止、状态仍为 `未知` 时，保留现有即时探测行为。
- 复用缓存时写入脚本运行日志，帮助用户知道状态来自后台探测。

## Impact

- 修改能力：`local-control-ui`
- 修改能力：`game-script-core`
- 不改变 `ScreenStateIs` 领域模型，不改变状态配置文件格式，不改变平台 adapter。
